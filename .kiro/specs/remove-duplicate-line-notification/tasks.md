# Implementation Plan

## Overview

このタスクリストは、LINE通知の重複を解消するための実装手順を定義します。ユーザー一覧通知を削除し、詳細データ通知のみを維持することで、1回のクローリング実行につき1つの統合された通知を送信します。

## Implementation Tasks

### Phase 1: コード削除と更新

- [x] 1. (P) メインワークフローからユーザー一覧通知呼び出しを削除
- [x] 1.1 (P) ユーザー一覧通知ブロックを削除し、ログ出力を更新
  - ユーザー一覧取得後の通知送信コードブロック（約15行）を削除
  - ユーザー一覧取得完了ログは維持（ユーザー数表示）
  - 通知送信関連ログ（送信中、完了、失敗）を削除
  - エラーハンドリングロジックを維持（`errors`配列への追加パターン保持）
  - ユーザー一覧取得失敗時の警告ログと処理継続を維持
  - _Requirements: 1.1, 1.2, 1.3, 1.4, 3.1, 3.5, 4.1_

- [x] 2. (P) 通知モジュールから不要な関数を削除
- [x] 2.1 (P) ユーザー一覧通知関数を削除
  - `sendUserListNotification`関数全体（約90行）を削除
  - `formatUserListMessage`関数全体（約10行）を削除
  - 他のファイルでこれらの関数が使用されていないことを確認
  - 詳細データ通知関連の関数（`formatDetailedMessage`, `truncateToLimit`）は維持
  - _Requirements: 3.2, 3.3, 3.5_

- [x] 3. (P) ドキュメントを更新
- [x] 3.1 (P) API仕様ドキュメントから削除関数の記述を削除
  - `sendUserListNotification`のAPI仕様セクションを削除
  - `formatUserListMessage`の仕様セクションを削除
  - 残存する関数（`formatDetailedMessage`, `truncateToLimit`）の記述は維持
  - ドキュメント全体の一貫性を確認
  - _Requirements: 3.4_

### Phase 2: 検証とテスト

- [ ] 4. 機能検証と統合テスト
- [ ] 4.1 詳細データ通知の機能維持を検証
  - 詳細データ通知にユーザー名が含まれることを確認
  - 学習時間、ミッション情報、点数変化が正しく表示されることを確認
  - ミッション変化アイコン（NEW ✨、📈、📉）が正しく機能することを確認
  - 複数ユーザーのセクション分けが正しく動作することを確認
  - メッセージフォーマットが既存パターンを維持していることを確認
  - _Requirements: 2.1, 2.2, 2.3, 2.4, 2.5_

- [ ] 4.2 通知送信の単一化を検証
  - GitHub Actionsワークフローを手動実行
  - LINE通知が1回のみ送信されることを確認
  - 通知内容が完全であることを確認（情報欠落なし）
  - 環境変数（`LINE_CHANNEL_ACCESS_TOKEN`, `LINE_USER_ID`）が正しく使用されることを確認
  - LINE Messaging API統合が正しく動作することを確認
  - _Requirements: 1.1, 1.5, 5.1, 5.3, 5.6_

- [ ] 4.3 ログ出力とエラーハンドリングを検証
  - ユーザー一覧取得完了ログが出力されることを確認
  - ユーザー一覧通知送信ログが**出力されない**ことを確認
  - 詳細データ通知の送信前・成功・失敗ログが正しく出力されることを確認
  - エラー発生時にエラーログが出力され、処理が継続することを確認
  - GitHub Actionsワークフローログで全ログが確認可能であることを確認
  - _Requirements: 1.3, 4.1, 4.2, 4.3, 4.4, 4.5_

- [ ] 4.4 後方互換性と非機能要件を検証
  - データ取得フローが変更されていないことを確認（ユーザー一覧取得は維持）
  - メッセージ長制限（5000文字）が遵守されることを確認
  - 既存のエラーハンドリングとリトライロジックが維持されることを確認
  - 通知送信処理の実行時間が増加していないことを確認
  - 認証情報のマスキングが正しく機能することを確認
  - _Requirements: 5.2, 5.4, 5.5_

- [ ]* 4.5 単体テストの作成（オプション）
  - `formatDetailedMessage`と`truncateToLimit`関数の単体テストを作成
  - `sendUserListNotification`と`formatUserListMessage`が存在しないことを確認するテスト追加
  - メッセージフォーマットが既存パターンと一致することを検証
  - ミッション変化アイコンが正しく表示されることを検証
  - 注: このタスクは受入基準を満たす追加的なテストカバレッジであり、MVP後に実施可能
  - _Requirements: 2.1, 2.2, 2.3, 2.4_

タスク4（検証）はPhase 1の完了後に実施。サブタスク4.1-4.4は順次実行を推奨（GitHub Actions実行は1回で全検証可能）。

### Manual Test Checklist
1. GitHub Actionsワークフローを手動トリガー
2. LINEで通知を**1回のみ**受信することを確認
3. 通知内容の完全性を確認（ユーザー名、学習データ、ミッション情報、点数変化）
4. GitHub Actionsログでログ出力を確認（ユーザー一覧通知ログの欠如を確認）
