# おたすけ満タンチャージ再適用(v1.3移行) 設計書

作成日: 2026-07-13
ステータス: ユーザー承認済み(今夜の手動再実行での即反映も承認)

## 背景(v1.2で不十分だった原因)

v1.2の満タンチャージ移行は「ファイルに既にいるユーザー」にのみ適用される。実際のタイムラインでは:

1. 2026-07-13 朝の実行がキャッシュ永続化後**初の**保存で、`streak_data.json`(v1.0)には中学生ユーザーだけが入った
2. 夜の実行(v1.2コード)はファイル内の中学生を3に移行したが、**小学生2人はファイル未登録**だったため移行対象外となり、新規ユーザーの初期値 `grace: 1` が適用された
3. 夜の保存でファイルがv1.2になり、一度きりの移行は発火済みになった

コードのバグではなく、移行適用と初回データ作成の順序の問題。

## 設計 (`src/streak.js` のみ)

v1.2と同じパターンでv1.3移行を追加する。今回は全ユーザー(小学生2人含む)がファイルに存在するため確実に適用される。

1. `saveStreakData` をバージョン `'1.3'` で保存
2. `loadStreakData` は `'1.0'`〜`'1.3'` を受理し、**1.3未満の読み込み時に全ユーザーの `grace = GRACE_MAX`(3)を設定**
3. 初期値1・リセット後0・上限3・ボーナスのルールは不変

## 反映手順

リリース後に夜クローラー(`crawler.yml`)を `workflow_dispatch` で手動実行する。前日確定は `lastConfirmedDate` の冪等性により二重判定されず、通知が今夜2通目として届き「おたすけ: 3/3」表示になる。

## テスト

- 1.2データの読み込みで grace 1 が 3 になること(v1.3チャージ対象)
- 1.3データの読み込みでは grace 0 でも変化しないこと
- 保存ファイルの version が 1.3 であること
- 1.0/1.1の既存移行テストは(1.3未満として)引き続き3チャージされること
