# Discord通知の分割送信 設計

作成日: 2026-08-03

## 背景

全通知をLINEとDiscordの両方へ送るようにした（`2026-08-03-always-dual-notification-design.md`）結果、
Discordの2000文字制限で末尾が切り詰められる日が常態化した。LINEは5000文字なので影響を受けない。
切り詰めるのではなく、2000文字ごとに分割して複数通で送る。

Discordには月間送信数の上限がないため、通数が増えても運用上の制約にならない。
LINEは分割しない。グループへのpushはメッセージ数×人数でカウントされ、無料枠（月200）を圧迫するため。

## 決定事項

### 分割の境界

行（`\n`）の境界で詰め込む。ユーザーごとのブロックが途中で割れにくくするため。
1行だけで上限を超える場合は、その行のみ文字単位で分割する。サロゲートペアは割らない
（絵文字が壊れるため）。

### ページ番号

分割が2通以上になる場合、各メッセージの先頭に `(1/3)` の行を付ける。
途中のチャンクが届かなかったときに欠けへ気づけるようにするため。1通で収まる場合は付けない。

ヘッダーの長さは分割数に依存するため、まず上限そのままで分割し、1チャンクに収まればそのまま返す。
2つ以上になる場合だけ、ヘッダー分を引いた幅で分割し直してからヘッダーを付ける。
ヘッダーの予約幅は16文字（`(10/10)\n` に十分な余裕を持たせた固定値）。

### 部分失敗の扱い

途中のチャンクが失敗しても残りのチャンクは送る。届く分は届けるため。
1つでも失敗したらDiscord送信全体を失敗として扱い、`{success: false, error: ...}` を返す。
エラー文には失敗したページ番号を含める（複数失敗時は連結）。
既存の `getDiscordFailure()` 経由で終了コード1になり、ワークフローが赤くなる。

## 実装

### `src/discord.js`

- `splitIntoChunks(message, maxLength)` を新設・エクスポートする。上記の分割規則を実装する純粋関数。
- 現行の `sendDiscordMessage()` のリトライループを内部関数 `sendSingleMessage()` に切り出す。
- `sendDiscordMessage()` は「分割 → 逐次送信 → 結果集約」を担う。Discord固有の文字数制限は
  Discordのモジュールが吸収し、呼び出し側は文字数を気にしない。
- チャンク間に `options.chunkDelay`（既定300ms）の待機を挟む。429はリトライで吸収できるが、
  無駄な往復を減らす。テストでは0を渡す。

### `src/broadcast.js`

`postToDiscord()` の `truncateToLimit(body, DISCORD_MAX_MESSAGE_LENGTH)` をやめ、全文を渡す。
LINE側の `truncateToLimit(message, LINE_MAX_MESSAGE_LENGTH)` は変更しない。

### DRY_RUN表示

- `src/index.js`: Discord単独送信日のプレビューを2000文字で切り詰めていたのをやめ、全文表示にする。
  切り詰めが起きなくなったため、プレビューと実際の送信内容が一致する。
- `src/index.js` / `src/morning-index.js`: 「Discordへは2000文字ごとに分割して送信します」の1行を出す。

## テスト

- `tests/discord.test.js`
  - `splitIntoChunks`: 短文は1チャンクでヘッダーなし / 行境界で割れる / 1行が上限超なら文字単位で割る /
    サロゲートペアを割らない / 2通以上ならヘッダーが付き、ヘッダー込みで上限に収まる
  - `sendDiscordMessage`: 長文で複数回POSTする / 2通目が失敗しても3通目を送る /
    1つでも失敗したら success:false で、エラーに失敗したページ番号が入る
- `tests/broadcast.test.js`: Discordへ切り詰めずに全文を渡す（既存の「2000文字に切り詰めて渡す」を差し替え）
