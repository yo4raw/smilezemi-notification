# 月次ボーナス清算の金額表示 設計

作成日: 2026-07-27

## 背景と目的

月次ボーナス清算の通知は、貯まったポイント数だけを伝えている。

```text
👤 はなこ (小学生コース): 2ポイント
```

実際に支給するのは現金なので、受け取る側も渡す側も毎回ポイントから金額を暗算している。通知に金額を載せて、そのまま渡せる状態にする。

単価はコースで分ける。小学生コースは 1ポイント = ¥30、中学生コースは 1ポイント = ¥50。

## 変更後のメッセージ

```text
💰 ボーナスポイント清算(7月分)

👤 たろう (中学生コース): 3ポイント → ¥150
👤 はなこ (小学生コース): 2ポイント → ¥60
👤 じろう (小学生コース): 0ポイント → ¥0

合計: ¥210
ボーナスポイントはお小遣いとして支給してね!
```

## スコープ

### やること

- `src/monthly-bonus-index.js` の `formatMonthlyBonusMessage()` に金額表示と合計行を追加する

### やらないこと

- **清算・リセットのロジックは変更しない**。`src/streak.js` の `settleBonuses()` も、リセット条件や終了コードの判定も触らない。今回変わるのは表示だけ
- **単価を環境変数や設定ファイルにしない**。コード内の定数に置く。変更頻度が低く、変更時にレビューを通したい種類の値のため
- **夜通知・朝通知のメッセージは変更しない**

## 設計

### 単価の定義

`src/monthly-bonus-index.js` の先頭に定数を置く。単価変更はここ1箇所の書き換えで済む。

```js
// ボーナスポイント1点あたりの金額(円)。コース別に単価が違う
const BONUS_POINT_YEN = {
  elementary: 30,
  juniorHigh: 50
};
```

### コース判定

`settleBonuses()` が返す `settlements` の要素は `{userName, bonus}` のみで、コース情報を持たない。ストリークデータ (`data/streak_data.json`) にもコースは保存されていない。

そのため `userName` の文字列から判定する。`userName` はクローラーが `"なまえ (中学生コース)"` の形で組み立てている（`src/crawler.js` の `displayName`）。

判定方法は既存の `src/notifier.js` と同じ慣例に揃える。

```js
const course = userName.includes('中学生コース') ? 'juniorHigh' : 'elementary';
```

コース選択がないユーザーは `userName` にサフィックスが付かず、小学生扱い（¥30）になる。既存コードと同じ扱いであり、現在の利用者は全員コース表記があるため実際には発生しない。

### 金額の書式

3桁区切りにする。おたすけ満タン中は学習した日ごとにボーナスが加算されるため、月31ポイント × ¥50 = ¥1,550 のように4桁になりうる。

`Number.prototype.toLocaleString('ja-JP')` を使う。整数のみを扱うため出力は決定的で、テストで固定値と比較できる。

### 合計行

各ユーザーの金額を合算し、ユーザー一覧の後に空行を挟んで `合計: ¥210` の形で出す。

**対象ユーザーが0人の月は合計行を出さない**。従来どおり「対象のユーザーがいませんでした。」だけを返す。

## テスト

`tests/monthly-bonus-index.test.js` の `formatMonthlyBonusMessage` に対するテストを追加する:

- 小学生コースのユーザーが 1ポイント = ¥30 で計算されること
- 中学生コースのユーザーが 1ポイント = ¥50 で計算されること
- 0ポイントのユーザーが `0ポイント → ¥0` と表示されること
- 合計行が全ユーザーの金額の合算になること
- 4桁の金額が3桁区切りで表示されること（例: 31ポイント × ¥50 = `¥1,550`）
- コース表記のないユーザーが小学生単価（¥30）で計算されること
- 対象ユーザーが0人のとき合計行が出ないこと

既存の清算フローのテスト（リセット条件・終了コード）は変更しない。

## 既知の制約

- **コース判定が表示名の文字列に依存する**。みまもるネット側のコース名表記が変わると単価判定が狂う。既存の `src/notifier.js` も同じ依存を持っており、本設計で新たに増える依存ではない。表記が変わった場合は両方を直す必要がある
- **過去分の遡及計算はしない**。金額表示は次回以降の清算通知から適用される
