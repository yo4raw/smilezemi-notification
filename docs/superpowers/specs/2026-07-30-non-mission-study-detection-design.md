# ミッション以外の学習の検出 設計

- 作成日: 2026-07-30
- 対象: 小学生コースのクロール・ストリーク判定・通知
- 関連: `docs/DOM_STRUCTURE.md`（実サイトのDOM構造リファレンス）

## 背景と課題

小学生コースのタイムラインには、ミッションとして配信された講座のほかに、
子どもが自主的に選んで取り組んだ講座も並んでいる。両者はDOM上、行内に
`[class*="missionIcon__"]`（「ミッション」バッジ）があるかどうかだけで区別される。

現行の `src/crawler.js` は `.missionIcon__i6nW8` の個数を数えているため、
**バッジのない自主学習は1件も検出できていない。**

実サイト調査（2026-07-30）で確認した例:

| 講座名 | ミッションバッジ | 学習結果 | 現行の扱い |
| --- | --- | --- | --- |
| こそあど言葉 | あり | 93点 / 1分 | カウント |
| 8級 同じ漢字の読み | あり | 目標80点 → 90点 / 7分 | カウント |
| 漢字のミニテスト | **なし** | 9/10 / 5分 | **未カウント** |
| ふしぎ探検 世界遺産 | **なし**（NEWのみ） | 4分 | **未カウント** |

同じ講座名でもミッションとして配信されればバッジが付き、自主的に選べば付かない。
ユーザーによって「漢字のミニテスト」のバッジ有無が分かれていた。

その結果、子どもが自主学習をしても連続学習日数（ストリーク）の判定に反映されず、
「やったのに数えられない」状態になっている。

### 中学生コースは対象外

中学生コースのタイムラインにはミッション概念そのものが存在せず、載っている行は
すべて学習実績である。教科欄には5教科のほか「英検」なども現れる。
つまり**中学生コースは既にミッション以外の学習も含めて取得できており、変更は不要**。

### コアトレは日別に取得できない

小学生の「学習のきろく > コアトレ」は週間学習数と分野別累計のみで、日別データを持たない。
中学生コースにはコアトレ画面自体がなく、URLを直接叩いても
`/study/c/timeline` にリダイレクトされる。よってコアトレは本設計の対象外とする。

### スターアプリは対象外

タイムラインにはスターアプリ（「ハムなかまっちならべ〜」「SUSHIショット」等）の
合計時間もアコーディオン行として並ぶが、ゲーム性が強いため学習として扱わない。
判定にも通知にも使わないので**取得しない**。ただし講座行として誤ってカウントしないよう、
行の識別（除外判定）だけは行う。

## 方針

小学生コースのタイムライン取得を、Y座標計算ベースから**行DOMベース**に作り直し、
講座行を「ミッション」「自主学習」に分類して両方カウントする。
ストリークの判定入力を「ミッション数」から「学習件数（ミッション＋自主）」に変える。
**しきい値は据え置く。**

## 1. クロール層

### 1.1 日ブロックの特定

現行のY座標による日付切り分け（`box.y > todayBox.y && box.y < nextDateY`）をやめ、
`dailyTimeline__` の日ブロック単位に置き換える。

```text
[class*="dailyTimeline__"] を走査
  └─ [class*="date__gE"] のテキストが対象日（MM/DD, ゼロパディングあり/なし両方）に
     一致するブロックを対象とする
```

タイムラインは直近7日分を保持し、スクロールしても8日目以降は読み込まれない。
朝通知が見る前日分は常に含まれる。

対象日のブロックが存在しない場合は「その日は未学習」として、
件数0・時間0・空配列を `success: true` で返す（現行の挙動を踏襲）。

### 1.2 行の分類

日ブロック内の `[class*="courseList__"]` の直下子要素を1行ずつ走査する。

```text
行に [class*="accordionRoot__"] が含まれる
  → スターアプリ行。カウントせず読み飛ばす
それ以外
  → 講座行
     isMission = 行内に [class*="missionIcon__"] があるか
     name      = [class*="title__"] のテキスト
     score     = [class*="scoreNumber__"] の数値（点数タイプ）
     correct   = [class*="correctAnswerCount__"] / [class*="questionCount__"]（正答数タイプ）
     minutes   = [class*="studyTime__"] のテキストをパース
```

`[class*="scoreLabel__"]`（「前回 93点」「目標80点」）は現在の点数ではないので使わない。
現行実装が `前回` を含むテキストを除外しているのと同じ意図を、構造で表現する。

### 1.3 学習時間

日ブロック左カラムの `[class*="totalStudyTime__"] > [class*="minute__"]` から取る。
`[class*="totalStar__"]`（スター獲得数）と兄弟要素なので、
親要素のテキストをまとめて読むと「6」+「89分」が連結されて誤読する。要素を分けて取ること。

なおこの学習時間にスターアプリの時間は含まれない（サイト側の仕様）。

### 1.4 セレクタの方針

全セレクタを `[class*="..."]` の前方一致にする。クラス名は CSS Modules のハッシュ付きで、
ビルドのたびに変わりうるため。

Y座標方式をフォールバックとして残すことはしない。両方式とも同じハッシュ付きクラス
（`missionIcon__i6nW8`）に依存しており、ハッシュが変われば揃って壊れるので、
二重化しても耐障害性は上がらず保守コストだけが増えるため。

### 1.5 中学生コース

クロール処理を変更しない。

## 2. データ構造

`missions` 配列の各要素に `isMission` を追加し、ユーザーデータに `studyItemCount` を追加する。

```js
{
  userName: 'たろう (小学生コース)',
  course: 'elementary',
  studyItemCount: 5,     // 追加: 講座行の総数（ミッション＋自主、スターアプリ除く）
  missionCount: 4,       // 維持: ミッションバッジ付きの数（通知の内訳表示に使う）
  date: '2026-07-30',
  studyTime: { hours: 0, minutes: 15 },
  totalScore: 343,
  missions: [
    { name: 'こそあど言葉', score: 93, completed: true, isMission: true,
      correctAnswers: null, questionCount: null },
    { name: '漢字のミニテスト', score: 0, completed: true, isMission: false,
      correctAnswers: 9, questionCount: 10 }
  ],
  dataReliable: true
}
```

学習結果には2タイプある。点数タイプ（`93点`）は従来どおり `score` に入れ、
正答数タイプ（`9/10`）は `correctAnswers` / `questionCount` に入れて `score: 0` とする。
どちらか一方だけが値を持ち、もう一方は `null`（点数タイプ）または `0`（正答数タイプの `score`）。
中学生コースでは正答数タイプが存在しないため、両フィールドとも常に `null`。

通知では `questionCount` が非 `null` の行を `9/10` 形式で、それ以外を `93点` 形式で表示する。

中学生コースでは `studyItemCount === missionCount === 講座数`、
`missions` の全要素が `isMission: true` となる。

`totalScore` の算出対象は変更しない（`missions` 全体の合計）。正答数タイプの行は
`score: 0` のままなので合計点には寄与しない。

### 差分比較

`src/data.js` の `compareData` の比較対象を `missionCount` から `studyItemCount` に変える。
「新しく学習した」の判定には自主学習も含めるべきであるため。

## 3. ストリーク判定

`src/streak.js` の判定入力を `missionCount` から `studyItemCount` に変える。
**しきい値（`STREAK_REQUIREMENTS`）は据え置き**:

- 小学生コース: 4件以上
- 中学生コース: 平日3件・土日5件以上

小学生では「ミッション4個以上」が「学習4件以上（ミッションでも自主でもよい）」になる。
ミッション4個以上なら学習件数も必ず4以上なので、現行で達成できていた日が
達成できなくなることはない。

### 後方互換

actions/cache に残る既存のユーザーデータには `studyItemCount` がない。
判定時は `studyItemCount ?? missionCount` でフォールバックし、既存データでも
現行と同じ結果になるようにする。

## 4. 通知

夜通知・朝通知のユーザーブロックで、件数行に内訳を付ける。

```text
👤 たろう (小学生コース)
📚 学習時間: 15分
✅ 学習5件（ミッション4・自主1）
🔥 連続12日 / おたすけ3 / ボーナス5
  ・こそあど言葉 93点
  ・小数のひき算 80点
  ・小数のたし算 80点
  ・8級 同じ漢字の読み 90点
  ・漢字のミニテスト 9/10（自主）
```

- 自主学習が0件のときは内訳を出さず `✅ 学習4件` とする
- 講座一覧では自主学習の行末に `（自主）` を付ける
- 中学生コースは全件がミッション扱いなので内訳も `（自主）` も出ない
  （表示は現行のまま）
- 未達警告の文言を「ミッションがあと◯個」→「学習があと◯件」に変更する。
  中学生は「講座」表記のまま変更しない

増える行は1人あたり最大1行（内訳は既存の件数行に併記）。メッセージは1通のままなので
LINEの月間送信カウントには影響しない。文字数上限は既存の `truncateToLimit` が扱う。

## 5. エラー処理

現行のグレースフルデグラデーション方針を維持する。

- 日ブロックが見つからない → 未学習として件数0で `success: true`
- 行の走査中に個別要素が取れない → その項目だけデフォルト値（名前は「ミッション」、
  点数0、時間0）にして継続
- 走査自体が例外を投げた → `success: false`。`getCourseData` がこれを
  `dataReliable: false` に伝搬し、ストリークの誤リセットを防ぐ

## 6. テスト

DOM抽出はPlaywright依存で単体テストが重いため、**集計ロジックを純粋関数として切り出す**。

- `summarizeStudyRows(rows)` — 行データ配列を受け取り
  `{ studyItemCount, missionCount, missions, totalScore }` を返す純粋関数。
  crawler がDOMから抽出した行データをこれに通す。ここを単体テストする
- `tests/crawler.test.js` — `summarizeStudyRows` のテストを追加
  （全ミッション / 混在 / 全自主 / 空配列 / 正答数タイプの行 / 点数タイプと正答数タイプの混在）
- `tests/streak.test.js` — `studyItemCount` ベースの判定、`missionCount` への
  後方互換フォールバック
- `tests/notifier.test.js` — 内訳付き件数行、自主0件時の表記、`（自主）` 印、
  変更後の警告文言
- `tests/data.test.js` — `studyItemCount` での差分比較
- `tests/index.test.js` — モックデータに `studyItemCount` / `isMission` を追加

DOM抽出そのものは `DRY_RUN=true node -r dotenv/config src/index.js` および
`src/morning-index.js` の実機実行で検証し、実サイトの値と突き合わせる。

## スコープ外

- 中学生コースのクロール処理変更（既に全学習を取得できているため）
- コアトレ・英語プレミアムの取得（日別データが存在しないため）
- スターアプリの取得・表示（学習として扱わないため）
- しきい値の変更
- 「学習のきろく > 月の学習」の日別グラフからの数値抽出
