# おたすけ初期値1 設計書

作成日: 2026-07-13
ステータス: ユーザー承認済み(リセット後の扱い・既存データへの適用・streak0ガードの3点を質疑で確定)

## 要件

おたすけ(grace)が最初0なのは可哀想なので、全員1にする。

## 確定した仕様判断

| 論点 | 決定 |
|------|------|
| 初期値 | 新規ユーザーは `grace: 1` から開始 |
| リセット後 | **0のまま**(現行どおり)。初回のみの特典であり、リセット後は10日連続で再獲得する |
| 既存ユーザー | **おたすけ0の人を1に引き上げる**(2以上の人はそのまま)。一度きりの適用で、以降消費して0になった分は再付与しない |
| streak 0時の消費 | **おたすけを消費しない**。守るべき記録がないのに初回特典が消えるのを防ぐ |

## 設計

### 1. 初期値 (`src/streak.js`)

- 定数 `GRACE_INITIAL = 1` を追加
- `createInitialState()` を `{ streak: 0, grace: GRACE_INITIAL, lastConfirmedDate: null }` に変更
- `confirmDay` のリセット分岐は現行どおり `grace: 0`(`createInitialState` を使わない)

### 2. データ移行(バージョン 1.0 → 1.1)

本番の `streak_data.json` は actions/cache 内にあり直接編集できないため、読み込み時に一度だけ移行する。

- `saveStreakData` はバージョン `'1.1'` で保存する
- `loadStreakData` は `'1.0'` と `'1.1'` を受理する。`'1.0'` の場合のみ、全ユーザーに `grace = max(grace, GRACE_INITIAL)` を適用する
- 未知バージョンは現行どおりエラー
- 移行は一度きり: 次回保存で `'1.1'` になるため、以降おたすけを消費して0になっても再付与されない

### 3. streak 0 のおたすけ非消費ガード (`confirmDay`)

未学習判定時、`streak === 0` なら守るべき記録がないため、おたすけを消費せず `lastConfirmedDate` だけ進める(event: `'none'`)。これがないと、新規ユーザーが最初に学習しなかった日に初回特典が無意味に消え、「💤 おたすけで連続記録を守りました」が streak 0 で表示される不自然な挙動になる。

判定順序: `studied` → `streak === 0`(非消費) → `grace > 0`(消費) → リセット。リセット分岐に到達するのは `streak > 0 && grace === 0` の場合のみになるため、event は常に `'reset'`。

### 4. 影響範囲

- 変更は `src/streak.js` のみ。通知表示(`grace/3` 表示)・クローラー・エントリポイント・ワークフローは無変更
- リリース後の初回実行(夜または朝)で 1.0 データが読み込まれた時点で移行が適用され、その回の保存から 1.1 になる

### 5. テスト (`tests/streak.test.js`)

- `createInitialState` が `grace: 1` を返す
- `confirmDay`: streak 0 + grace 1 + 未学習 → grace 1 のまま・event `'none'`・日付は確定
- `confirmDay`: リセット後は grace 0(既存テスト維持)
- `loadStreakData`: 1.0ファイル → grace 0 が 1 に引き上げ、grace 2 はそのまま / 1.1ファイル → grace 0 でも引き上げなし / 未知バージョンはエラー(既存)
- `saveStreakData`: version `'1.1'` で保存される
- ラウンドトリップ: save → load で grace が変化しない
- `updateStreaks`: 新規ユーザーの初日学習で `{streak: 1, grace: 1}`
